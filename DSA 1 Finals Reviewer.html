Lesson 9

Queue

A queue is a line. First in, first out. Whoever has waited longest is served next.

1. What a queue is

Picture the line at a bus ticket counter. New people join at the back. The cashier serves the person at the front. Nobody can cut in, and nobody is served from the middle. That is the whole idea.

enqueue →
D
C
B
A
→ dequeue

D just joined at the back (tail). A has waited longest and leaves first from the front (head).

  • FIFO
    First-In-First-Out, the rule of a queue.
  • Front / head
    Where items leave. Oldest item.
  • Back / rear / tail
    Where items join. Newest item.
  • Underflow
    Trying to dequeue from an empty queue.

2. The operations

OperationWhat it doesResult in the lesson's codeTime
enqueue(x)Adds x at the backReturns nothing. Prints x has been added to the queue.O(1)
dequeue()Removes the front itemReturns the removed value. If empty: prints Queue Underflow: No elements to dequeue. and returns nullO(1)
peek()Looks at the front, removes nothingReturns the front value. If empty: prints No elements to display. and returns nullO(1)
isEmpty()Checks head == nullReturns true or falseO(1)
Exam trap

None of these operations returns an index or position. Dequeue returns the value it removed. Enqueue returns nothing useful. Posttest items 2 and 8 test exactly this.

3. Why enqueue and dequeue are O(1)

The lesson builds the queue from linked-list nodes. Each Node holds data and a next link. The Queue keeps two pointers: head and tail.

head → [7] → [3] → [9] → null
                      ↑
                    tail
  • enqueue uses tail to attach the new node. No walking.
  • dequeue uses head to detach the first node. No walking.
Remember

If the queue kept only a head pointer, enqueue would have to walk the whole list to find the end. That is O(n). The tail pointer is the reason it is O(1).

4. Reading the code

public void enqueue(int data) {
   Node newNode = new Node();
   newNode.setData(data);

   if (isEmpty()) {
      head = tail = newNode;      // first item: head and tail are the same node
   } else {
      tail.setNext(newNode);      // old last node points to the new one
      tail = newNode;             // tail moves to the new node
   }
   System.out.println(data + " has been added to the queue.");
}

public Integer dequeue() {
   if (isEmpty()) {
      System.out.println("Queue Underflow: No elements to dequeue.");
      return null;
   }
   int value = head.getData();    // save the front value
   Node newHead = head.getNext(); // remember the second node
   head.setNext(null);            // cut the old head loose
   head = newHead;                // second node is now the front

   if (head == null) {            // queue became empty
      tail = null;                // so tail must be cleared too
   }
   return value;
}
Why tail = null?

If the last item is removed and tail still points at it, the next enqueue would attach to a node that is no longer in the queue. Clearing tail keeps an empty queue truly empty (head == tail == null). A common "why is this line here" question.

6. Where queues are used

Anything that says "in the order received" is a queue.

Operating systems

CPU scheduling (processes wait for CPU time). Print queue (documents print in order).

Buffers

Streaming and video playback. I/O buffers such as the keyboard input buffer, because devices run at different speeds.

Messaging

Message queues between processes or threads. SMS and email systems.

Service lines

Call centers, airline ticketing, checkout lines, traffic management simulations.

Lesson 10, part 1

Binary Tree

A tree stores data as a hierarchy. In a binary tree, every node has at most two children: a left and a right.

1. Why trees exist

Arrays and linked lists are linear. To find something you check one element after another, which is O(n) in the worst case. A tree is nonlinear: each node can branch to several others, like folders inside folders or an org chart. A tree can also be empty (no nodes at all).

2. The vocabulary, on a real tree

Tap a term to see which nodes it means. Terms are the easiest marks on the exam.

  • Node
    One element: holds data (the key) and may have children.
  • Edge
    The link between two nodes.
  • Path
    The sequence of nodes along edges.
  • Root
    Topmost node. Level 0. Everyone descends from it.
  • Parent / Child
    A parent has one or more children. Any node except the root has exactly one parent.
  • Siblings
    Children of the same parent.
  • Leaf
    A node with no children. A terminal node.
  • Subtree
    A node plus all its descendants, treating that node as the root.
  • Level
    Number of edges from the root to the node. Root is 0.
  • Key
    The value stored in a node.
Exam trap

The root is the first node. The leaf is the last, with no children. Posttest item 7 swaps them.

Beyond the slides, but easy to ask

A tree with n nodes has n − 1 edges. Level L holds at most 2L nodes. A binary tree of height h holds at most 2h+1 − 1 nodes (height 3 gives 15).

Binary tree is not the same as binary search tree. A plain binary tree has no ordering rule. It only limits each node to two children. The sorted-order rule belongs to the BST (next tab).

3. Traversal: visiting every node

You cannot jump to a node in a tree. You always start at the root and follow edges. There are three standard orders, and all three are recursive. The only difference is when the root of each subtree is visited.

TraversalPatternMemory hookResult for the A to G tree
Pre-orderRoot, Left, Rightroot comes pre, before its childrenA B D E C F G
In-orderLeft, Root, Rightroot sits in the middleD B E A F C G
Post-orderLeft, Right, Rootroot comes post, after its childrenD E B F G C A

Watch the three orders walk the same tree. Use Step to move one node at a time.

Remember

In-order on a binary search tree gives the keys sorted in ascending order. This is the most tested fact about traversals.

The hand shortcut (no recursion needed)

Draw a small dot next to every node: on its left side for pre-order, underneath for in-order, on its right side for post-order. Now trace a line around the outside of the tree, starting left of the root and hugging every branch. Read the dots in the order the line touches them. That is your answer.

What the recursion really does

public void printInorder(Node node) {
   if (node == null)
      return;                          // nothing here, go back up
   printInorder(node.getLeft());       // 1. whole left subtree first
   System.out.print(node.getKey() + " "); // 2. then this node
   printInorder(node.getRight());      // 3. then the whole right subtree
}

For a tiny tree with A as root, B on the left, C on the right, printInorder(A) runs like this:

  1. Call on A. Its left is B, so call on B.
  2. Call on B. Left is null, returns. Print B. Right is null, returns. Back to A.
  3. Print A.
  4. Call on C. Left is null, returns. Print C. Right is null, returns.

Output: B A C. Pre-order and post-order differ only in where the print line sits: first line for pre-order, last line for post-order.

4. Inserting into a binary tree

The Lesson 10 insert() fills the first empty spot it finds scanning the tree level by level, left to right. It uses a queue to do the scanning, which is why the queue lesson comes first.

  1. Put the root in a queue.
  2. While the queue is not empty, take the front node out.
  3. If its left child is empty, put the new node there and stop. Otherwise add the left child to the queue.
  4. If its right child is empty, put the new node there and stop. Otherwise add the right child to the queue.
  5. Repeat.

Type keys into the lab. The log shows the queue at work for the last key you inserted. Try the lesson's sample: 10 11 7 9 15 8 13 12.

Exam trap

This insertion does not compare values. 5 can end up left of 50 or right of 50. It only cares about the next empty spot. Comparing values is what a BST does.

OperationTimeReason
Traversal (pre, in, post)O(n)Each of the n nodes is visited once.
Level-order insertO(n)In the worst case the queue passes through most of the tree.
Search in an unordered binary treeO(n)No order, so any node could hold the key.
Recursion depthO(h)Pending calls equal the height of the tree.

7. Programming task: recursive factorial

Factorial is the classic first recursion. n! = n × (n−1) × … × 1, and 0! = 1. The two things graders look for: a base case that stops the recursion, and a recursive case that moves toward it.

public class Factorial {

   // returns n! for a non-negative integer n
   public static long factorial(int n) {
      if (n < 0) {
         throw new IllegalArgumentException("n must be non-negative");
      }
      if (n == 0) {
         return 1;                    // base case: 0! is defined as 1
      }
      return n * factorial(n - 1);    // recursive case: n! = n * (n-1)!
   }

   public static void main(String[] args) {
      System.out.println("5! = " + factorial(5));   // 5! = 120
      System.out.println("0! = " + factorial(0));   // 0! = 1
   }
}

How factorial(4) unfolds. Calls go down until the base case, then the answers multiply on the way back up:

factorial(4) = 4 * factorial(3)
                   = 3 * factorial(2)
                         = 2 * factorial(1)
                               = 1 * factorial(0)
                                     = 1        ← base case
back up:  1  →  1*1 = 1  →  2*1 = 2  →  3*2 = 6  →  4*6 = 24

Time is O(n) (n calls). Space is O(n) too, because n calls wait on the stack. The rubric: Functionality 6, Readability 2, Efficiency 2. Readability means a consistent coding style and comments on the important lines.

Lesson 10, part 2

Binary Search Tree

A BST is a binary tree with a rule: smaller goes left, bigger goes right. That rule makes searching fast.

1. The two properties

  • Binary tree structure: each node has at most two children, left and right.
  • Ordering property: for every node N, everything in its left subtree is less than N and everything in its right subtree is greater than N.

Think of a number-guessing game ("higher or lower?"). Each answer lets you ignore half of what is left. A BST bakes that game into the structure.

Remember

Because of the ordering property, in-order traversal of a BST is sorted ascending. The smallest key is the leftmost node. The largest is the rightmost.

Duplicates

The lesson's insertNode only goes left for < and right for >. An equal key does neither, so the tree comes back unchanged. Inserting the same key twice adds nothing.

2. Inserting and searching

Insert: always lands on a leaf

Start at the root. Compare. Go left if smaller, right if bigger. Keep going until the spot you need is empty, and put the new node there. A new node is always a leaf.

The lesson inserts 10, 5, 2, 15, 18, 12, 3, 1:

  • 10: tree is empty, so it becomes the root.
  • 5 < 10, left is empty. Left child of 10.
  • 2 < 10, then 2 < 5, left of 5 is empty. Left child of 5.
  • 15 > 10, right is empty. Right child of 10.
  • 18 > 10, then 18 > 15. Right child of 15.
  • 12 > 10, then 12 < 15. Left child of 15.
  • 3 < 10, 3 < 5, 3 > 2. Right child of 2.
  • 1 < 10, 1 < 5, 1 < 2. Left child of 2.

Search: the same walk, without inserting

Equal to the node: found. Smaller: go left. Bigger: go right. Reached null: not in the tree. Lesson example: Find(7) goes 10 → 5 → 6 → 7.

Use Insert next to replay the lesson one key at a time, then search for keys. The log shows each comparison.

3. Time complexity

The cost of insert or search is the number of nodes on the path, which is the height of the tree.

Balanced: O(log n)

The tree is bushy. Each comparison halves the remaining nodes. 1,000 keys need about 10 comparisons.

Skewed: O(n)

Every node has only one child, so the tree is a chain. 1,000 keys can need 1,000 comparisons. Same as a linked list.

Exam trap

Inserting keys that are already sorted (1, 2, 3, 4, 5) makes a skewed tree. The structure does not balance itself. The lab above has a "sorted" preset: try it and watch the height grow.

How many comparisons in the worst case? Try your own n:

4. Reading the code

// returns the (possibly new) root of this subtree
public Node insertNode(Node root, int key) {
   if (root == null) {                       // found the empty spot
      root = new Node(key);
      return root;
   }
   if (key < root.getKey())
      root.setLeft(insertNode(root.getLeft(), key));    // smaller: go left
   else if (key > root.getKey())
      root.setRight(insertNode(root.getRight(), key));  // bigger: go right
   return root;                               // equal key: nothing changes
}

public Node searchNode(Node root, int key) {
   if (root == null || root.getKey() == key)
      return root;                            // null = not found, else found
   if (root.getKey() > key)
      return searchNode(root.getLeft(), key);
   return searchNode(root.getRight(), key);
}

Notice root.setLeft(insertNode(...)). The recursive call returns the subtree root, and that gets re-attached on the way back. That is how the new leaf is linked in.

Lesson 11

Graph

A graph is a set of dots (vertices) joined by lines (edges). It models relationships: friends, roads, links, dependencies.

1. The vocabulary

"Graph" here is not a bar chart. It is the dots-and-lines structure from graph theory.

  • Vertex (node)
    A dot: a person, city, web page.
  • Edge
    A line between two vertices. Can be directed (arrow), undirected, or weighted (carries a number).
  • Degree
    Number of edges touching a vertex.
  • In-degree / out-degree
    Directed graphs only: arrows coming in / going out.
  • Path
    A sequence of vertices where each neighbor pair is joined by an edge. Its length is the number of edges.
  • Cycle
    A closed path: starts and ends at the same vertex.
  • Connected
    A path exists between every pair of vertices. Otherwise disconnected, which splits into connected components.
  • Tree
    A graph that is connected and has no cycles.
Undirected graphDirected graph (digraph)
Edgeplain line, symmetric: A–B means B–Aarrow, can be one-way: A→B does not imply B→A
Edge notationunordered pair {1,2} with curly bracesordered pair (1,2) with parentheses
Degreeone number per vertexin-degree and out-degree
Modelsfriendships, roads, computer networksweb links, following, software dependencies, information flow

2. Defining a graph: G = (V, E)

V is the set of vertices and E is the set of edges.

Example 1: undirected

V = {1,2,3,4}
E = {{1,2},{2,4},{3,4},{4,1}}

Degrees: 1 → 2, 2 → 2, 3 → 1, 4 → 3. They add up to 8, which is 2 × 4 edges.

Example 2: directed

V = {1,2,3,4,5}
E = {(1,3),(1,4),(2,3),(2,5),(3,5),(4,5)}

In-degree of 5 is 3. Out-degree of 1 is 2. Vertex 5 has out-degree 0.

Remember

Handshake rule: in an undirected graph, the sum of all degrees equals 2 × the number of edges, because every edge is counted at both ends. In a directed graph, total in-degree equals total out-degree equals the number of edges.

A tree is a graph, so tree facts apply: a connected graph with n vertices and n − 1 edges is a tree (posttest item 7).

3. Euler, Hamilton and bipartite

Eulerian circuit

A closed loop that uses every edge exactly once and returns to the start.

Undirected and connected: it exists exactly when every vertex has an even degree.

Used in route planning, mail delivery and maze or puzzle design.

Hamiltonian cycle

A closed loop that visits every vertex exactly once and returns to the start.

There is no simple even-degree test. It is hard to decide in general.

Bipartite graph

Vertices split into two groups with no edge inside a group. Edges only go between the groups.

Same as: no odd-length cycle. Models two kinds of things, like students and courses.

Remember

Euler = Edges, each once. Hamilton = every vertex (think "Hops to every stop"), each once. Both return to the start when they are a circuit or cycle.

Exam trap

A Hamiltonian path visits every vertex once but does not have to return to the start. The version that returns is the Hamiltonian cycle. Posttest item 5 describes a cycle and calls it a path.

Beyond the slides

An Eulerian path (not closed) exists when there are exactly 0 or 2 vertices of odd degree. The lab below reports this.

5. The lesson's program, in one picture

The program stores a list of vertices. Each Vertex holds its data and its own list of neighbors. This is an adjacency list. addEdge(a, b) finds both vertices and adds each to the other's neighbor list, so the graph is undirected.

public void addEdge(int data1, int data2) {
   Vertex v1 = findVertex(data1);
   Vertex v2 = findVertex(data2);
   if (v1 != null && v2 != null) {
      v1.getNeighbors().add(v2);   // a knows b
      v2.getNeighbors().add(v1);   // b knows a
   } else {
      System.out.println("One or more vertices not found.");
   }
}

Neighbors appear in the order edges were added. That order is what output-tracing questions test.

Lesson 12

Hash Maps

A map stores key → value pairs. A hash map uses a formula on the key to jump straight to where the pair lives.

1. Map and hash map

  • Key-value pair
    Each entry links a key to a value, like a word and its definition.
  • Unique keys
    Two entries cannot share a key.
  • Values may repeat
    Two different keys can hold the same value.
  • Fast lookup
    Give the key, get the value back quickly.

Analogy: a coat check. You hand over a coat and get a numbered tag. Later, the number tells the attendant exactly which hook to check, with no searching through every coat. The hash function is the rule that turns the key into the hook number.

The lesson's hash function:

hash(key) = key % array_size        (% is the remainder after division)

With an array of size 7, hash(10) = 10 % 7 = 3, so the pair goes to index 3. The index is always between 0 and size − 1.

Remember

Lookup works by key, never by index. The hash function computes the index for you. Posttest item 10 ("values are accessed by their index") is false.

2. Collisions and linear probing

A collision happens when two different keys hash to the same index. 10, 17 and 24 all give % 7 = 3.

Linear probing is the lesson's fix: if the slot is taken, try the next one, then the next, until an empty slot appears. At the end of the array, wrap around to index 0.

The lesson's sequence, array size 7:

OperationHashWhat happensPlaced at
Insert (10, A)10 % 7 = 3Slot 3 is empty.3
Insert (17, B)17 % 7 = 3Collision with 10. Try 4: empty.4
Insert (24, C)24 % 7 = 33 taken, 4 taken. Try 5: empty.5
Insert (15, D)15 % 7 = 1Slot 1 is empty.1

Searching follows the same path

  • Search 15: hash to index 1, the key there is 15. Found immediately. Return "D".
  • Search 24: hash to index 3, which holds 10, not 24. Probe 4 (holds 17), then 5 (holds 24). Found, return "C".

Searching stops when:

  • the key is found: success;
  • an empty slot is reached: the key is not in the map;
  • the probing has looped all the way back to the start: the key is not in the map.
Why an empty slot means "not here"

When the key was inserted, it took the first empty slot along its probe path. So if the search finds an empty slot before the key, the key was never inserted.

Beyond the slides, but a favorite follow-up

Deleting an entry cannot just empty its slot. That would create a hole that stops later searches too early, so real implementations leave a "deleted" marker. Also, when the table gets too full (a high load factor, the entries divided by the table size), collisions pile up, so real hash maps grow and rehash.

4. Time complexity

CaseInsert / search / deleteWhy
AverageO(1)Hash gives the slot directly. Collisions are rare and short.
WorstO(n)Every key collides, so probing walks across most of the table.
Exam trap

Hash map search is O(1) on average, not O(log n). O(log n) is the balanced BST. A hash map also does not keep keys in sorted order.

Hash map vs BST: if you need fast lookup and do not care about order, use a hash map. If you need the keys in sorted order, use a BST (its in-order traversal).

5. Applications

Caching and memoization

Store results of expensive computations so recursion and dynamic programming do not repeat work.

Lookup tables

Dictionaries: look up a word, find its definition.

Frequency counting

Count how often each word appears. Also grouping data, such as students by first initial.

Indexing

Databases and search engines map IDs or keywords to entries. A set can be built from just the keys.

Compilers

Symbol tables map variable names to types, memory locations or values.

Networks and login

Routing tables map IP addresses to routes. Authentication maps usernames or session tokens to accounts. Games track scores and inventory.
